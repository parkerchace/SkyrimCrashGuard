[center][size=5][b]Overview[/b][/size][/center]

Skyrim Crash Guard is an SKSE plugin that attempts to recover from crashes in real-time instead of just logging them. When your game would normally crash, this mod tries to catch it and keep you playing. [b]This approach is inherently risky[/b] as it allows the game to continue running after a crash, potentially in a corrupted state.

[b]Who is this for?[/b] People with thousands of mods who want to keep playing instead of crashing. People who debug mods and want to collect multiple crash logs in one session. As I see it: [i]Why crash for one log? Catch exceptions, keep running, and batch-collect your debug data.[/i]

[b]How it works:[/b] The mod uses Vectored Exception Handling (VEH), a Windows feature that lets programs intercept crashes before they happen. When a crash occurs, the mod analyzes it and attempts recovery through progressively more aggressive strategies. Some crashes can be recovered, many cannot.

[b]Compatibility:[/b] Skyrim SE 1.5.97, AE 1.6.x (all versions), Skyrim VR 1.4.15
[b]Status:[/b] v2.3.2

[list]
[*][b]Crash Recovery:[/b] Intercepts crashes (null pointers, corrupted objects, particle effects, skeleton issues) and attempts to fix them on the fly

[/list]

[b]Real-time monitoring:[/b] F11 menu shows live stats, crash history, and lets you adjust settings without restarting.

[center][size=5][b]FAQ[/b][/size][/center]

[b]Q: Will this prevent ALL crashes?[/b]
A: No. No mod can prevent 100% of crashes. Crash Guard attempts to recover from some common crash types (null pointers, vtable corruption, access violations), but many crashes cannot be recovered. Even "successful" recoveries may leave the game in an unstable state. Some crashes (stack overflow, heap corruption, hardware/driver failures) are explicitly rejected because recovery would be unsafe. This is experimental software with unpredictable results. It may help in some scenarios but can also cause new problems.

[b]Q: Does this replace Crash Logger/Trainwreck?[/b]
A: No, they complement each other. Crash Guard attempts to catch and recover from crashes (and logs them with detailed context), while Crash Logger/Trainwreck handle the unrecoverable ones with full memory dumps. Many users run both for maximum coverage.

[b]Q: Will this work with my heavily modded load order?[/b]
A: It's designed to work with modded setups. The memory monitoring tells you when you're approaching resource limits, helps you identify mod conflicts, and the crash avoidance keeps you playing for longer. However, no mod can fix fundamental conflicts, broken mods, or missing masters. Results will vary.

[b]Q: Is this safe for my save files?[/b]
A: [b]No.[/b] When the mod recovers from a crash, the game continues running in a potentially corrupted state (corrupted memory, stack, heap, or game objects). Any saves made after a recovery may contain hidden corruption. The "save protection" features are experimental attempts to reduce risk, but they [b]cannot guarantee save safety[/b]. Save corruption is possible and may manifest sessions later. [b]Always maintain external backups. Do not rely on this mod to protect your saves.[/b]

[b]Q: What crashes CANNOT be recovered?[/b]
A: Stack overflow, heap corruption, system DLL internal crashes (ntdll.dll, kernel32.dll, VCRUNTIME140.dll), CrashGuard's own crashes, crashes during game exit, and crashes after cascade protection limits are exceeded. These will be logged by CrashLogger/Trainwreck if installed.

[center][size=5][b]Technical Details[/b][/size][/center]

[size=4][b]7-Layer Recovery Chain[/b][/size]
When a crash occurs, Crash Guard attempts recovery through progressively more aggressive strategies:

[list=1]
[*][b]L1: Known Site Recovery[/b]
Pre-analyzed crash addresses for the game and mod DLLs. Attempts instant recovery with zero decoding overhead. Supports both normal mode (zero register, skip instruction) and bailout mode (exit entire function to prevent cascade crashes).

[*][b]L1b: Instruction Pattern Matching[/b]
Version-independent recovery using Zydis disassembler. Matches semantic patterns instead of fixed offsets. Handles 4 instruction patterns:
  • P1: Indirect calls with bad base (null vtable) → function return
  • P2: Indirect jumps with bad base → function return
  • P3: Reads from null/invalid pointers → zero destination register, skip instruction
  • P4: Writes to null/invalid pointers → skip write (game code) or function return (system DLLs)

[*][b]L2: Learned Site Cache[/b]
Fast-path cache for crashes previously decoded by L4. Stores up to 512 learned sites with zero decoding overhead for future crashes at the same location.

[*][b]L3: Register Fixup[/b]
Redirects faulting base register to point into 64KB safety buffer and re-executes the same instruction. Includes cascade protection (max 3 hits per location, max 4 fires in 100ms window).

[*][b]L4: Instruction Skip[/b]
Decodes faulting instruction with Zydis, zeros destination register, advances RIP past the instruction. Caches result in L2 for future hits. Uses function return instead of skip for CALL/JMP instructions.

[*][b]L5: Function Return[/b]
Pops return address from stack, sets RAX=0 (null return value), jumps to caller. Validates RSP is readable and return address is in executable memory.

[*][b]L6: Deep Stack Walk[/b]
Scans up to 8KB of stack for executable pointers. Uses CALL instruction heuristics to reduce false positives. Last resort recovery attempt.
[/list]

[size=4][b]Cascade Protection[/b][/size]
Multi-layer protection to prevent infinite recovery loops:
[list]
[*][b]Global limit:[/b] Max 100 crashes in 5 seconds (trips cascade breaker, 10-second cooldown)
[*][b]Function-level tracking:[/b] Max 30 crashes per 256-byte function block (5-second reset window)
[*][b]Recovery cooldown:[/b] 5ms minimum between recoveries (prevents rapid-fire loops)
[*][b]Per-RIP limits:[/b] L3 Register Fixup limited to 3 hits per location before escalating to L4/L5
[*][b]Special handling:[/b] Moon/Sky rendering gets elevated limit (200 crashes) during save load for SkyrimSoulsRE compatibility
[/list]

When cascade limits are exceeded, CrashGuard stops attempting recovery to prevent making things worse.

[center][size=5][b]Detailed Feature Documentation[/b][/size][/center]

[size=4][b]Crash Recovery (Detailed)[/b][/size]

[b]What crashes can be recovered:[/b]
[list]
[*]Null pointer crashes: accessing memory that doesn't exist (most common)
[*]Corrupted vtables: broken function pointers in game objects
[*]Fire spell particle crashes: pFireballCore06-Emitter, MPSFireBoltImpact01
[*]NPC skeleton crashes: during LOD transitions or animation loading
[*]Moon/Sky rendering crashes: during save/load operations
[*]RaceMenu overlay/morph null pointers: character customization crashes
[*]Invalid memory reads/writes: accessing freed or invalid memory regions
[/list]

[b]What crashes cannot be recovered:[/b]
[list]
[*]Stack overflow: too many nested function calls
[*]Heap corruption: memory management system is broken
[*]System DLL crashes: ntdll.dll, kernel32.dll, VCRUNTIME140.dll internal errors
[*]Hardware/driver failures: GPU crashes, audio driver crashes (XAudio2_7.dll)
[*]Crashes during game exit: game is shutting down anyway
[*]Cascade protection exceeded: too many crashes in rapid succession (safety limit)
[/list]

[b]How recovery works:[/b]
The mod uses a 7-layer recovery chain, trying progressively more aggressive strategies until one works. Each layer has different success rates and safety profiles. When a crash occurs, the mod analyzes the crash type, identifies the faulting instruction, and applies the appropriate recovery strategy. If recovery succeeds, the game continues running. If all layers fail, the crash is passed to CrashLogger/Trainwreck for logging.

[size=4][b]Proactive Validation (Detailed)[/b][/size]

[size=4][b]Mesh Validation[/b][/size]
Provides validation utilities for 3D models when explicitly called:
[list]
[*]Status: Implemented as utility functions (not automatically integrated into mesh loading pipeline)
[*]Vertex checks: validates vertex count (must be >0) and positions (no NaN/Inf values)
[*]Normal checks: verifies surface normals are unit length and valid (used for lighting calculations)
[*]Texture coordinate checks: ensures UV coordinates are finite and valid for texture mapping
[*]Triangle checks: verifies mesh has at least 3 vertices to form triangles
[*]Bone weight checks: for skinned meshes, validates bone indices are in range and weights sum to 1.0
[*]Smart skipping: NiNode scene containers are trusted without deep inspection (performance optimization)
[*]Lenient approach: only extremely broken models are rejected (permissive validation reduces false positives)
[*]Integration: Available for use by crash recovery systems and manual validation calls
[/list]

[b]Repair capabilities:[/b]
[list]
[*]Can generate missing texture coordinates using planar UV mapping (XY projection, fully implemented)
[*]Can allocate missing normal arrays and set to up vector (0,0,1) - not true calculation from triangles
[*]Can replace NaN/Inf values with safe defaults (0.0 for positions, up vector for normals)
[*]Can clamp bone weights to valid range [0.0, 1.0]
[*]When repair fails: returns nullptr and lets game handle it (may cause visual glitch or crash)
[/list]

[size=4][b]Papyrus Validation[/b][/size]
Validates parameters for specific problematic Papyrus native functions:
[list]
[*]Status: Implemented with limited function coverage (currently validates 1 function: SmartHarvest::NotifyActivated)
[*]Null checks: validates objects, items, and strings aren't null before scripts use them
[*]Type checks: ensures scripts pass correct data types (Actor vs ObjectReference vs Form)
[*]Form checks: verifies game objects exist and are loaded before scripts reference them
[*]Array checks: validates array indices are in bounds and array data is valid
[*]String checks: ensures text data is valid and not corrupted
[*]Safe fallbacks: replaces broken data with safe defaults (empty string, null form, zero value)
[*]Expansion: Additional functions can be registered for validation as needed
[*]Tracking: counts how many problems were caught and fixed (visible in F11 menu)
[/list]

[size=4][b]FormID Validation[/b][/size]
Checks game object IDs before looking them up to prevent crashes:
[list]
[*]Format checks: ensures FormID is non-zero and in valid range
[*]Plugin checks: verifies the mod that owns this FormID is actually loaded
[*]Existence checks: confirms the object exists in TESDataHandler before trying to use it
[*]Type checks: validates you're getting the right kind of object (Actor vs Weapon vs Armor)
[*]Caching: remembers valid FormIDs to avoid repeated lookups (performance optimization)
[*]Invalid tracking: remembers broken FormIDs to skip them immediately next time
[*]Safe lookups: returns nullptr instead of crashing when a FormID is invalid
[*]Mod identification: resolves FormID to plugin name for debugging (e.g., "Skyrim.esm", "MyMod.esp")
[/list]

[size=4][b]Script Monitoring[/b][/size]
Watches Papyrus scripts while they run to catch problems:
[list]
[*]Execution time tracking: measures how long each script takes to run (milliseconds)
[*]Timeout detection: catches scripts that run too long (infinite loops, heavy calculations)
[*]Stack depth monitoring: detects scripts calling themselves repeatedly (recursion depth)
[*]Memory tracking: watches how much memory scripts allocate (heap usage)
[*]Error logging: records script errors with full context for debugging
[*]Performance profiling: identifies slow scripts that impact framerate
[/list]

[size=4][b]Cell Validation[/b][/size]
Checks game areas (cells) before loading them to prevent crashes:
[list]
[*]Cell structure checks: validates cell data isn't corrupted (FormType is Cell, flags are consistent)
[*]Object checks: validates all objects in the cell before spawning them
  - Checks if base form exists and is loaded  - Validates position is finite (no NaN/Inf coordinates)  - Ensures FormID is valid and object isn't deleted  - Verifies object isn't disabled or marked for deletion[*]Invalid object detection: finds and logs broken objects (cannot remove them due to CommonLibSSE API limitations)
[*]Circular reference detection: catches objects that reference each other in loops (prevents infinite iteration)
[*]Cell blacklisting: remembers problem cells that cause crashes and blocks them from loading (max 1000 entries)
[*]Safe cell tracking: maintains list of known stable locations for emergency teleportation
  - Whiterun (main city, very stable)  - Riverwood (starting village, stable)  - Solitude (capital city, stable)  - Windhelm (major city, stable)  - Riften (major city, stable)  - Markarth (major city, stable)  - Helgen Keep (tutorial interior, very stable)[/list]

[b]Limitations:[/b]
[list]
[*]Validation is best-effort and cannot catch all potential issues before they occur
[*]Some crashes happen too quickly for proactive validation to intercept (race conditions)
[*]Validation adds minimal overhead (~1-2% performance impact) but cannot prevent all crash types
[*]Complex mod interactions may bypass validation checks (mods that hook the same functions)
[*]Validation focuses on common crash patterns but cannot cover all edge cases
[*]Cell validation cannot remove invalid objects, only detect and log them (API limitation)
[/list]

[size=4][b]NPC Management (Detailed)[/b][/size]

[b]Smart Protection System:[/b]
The mod never deletes NPCs that are important to the game or your playthrough:
[list]
[*]Never deletes: player, player teammates/followers
[*]Never deletes: essential NPCs (marked essential in game data)
[*]Never deletes: unique/important NPCs (Lydia, Balgruuf, Elisif, Ulfric, etc.)
[*]Keyword-based whitelist/blacklist: configurable protection for specific NPC types
[*]Safe to delete: generic enemies (bandits, draugr, forsworn, vampires, skeletons, spiders, wolves, bears, saber cats), guards (they respawn), soldiers, generic citizens
[/list]

[b]How It Works:[/b]
[list]
[*]Default threshold: 50 NPCs (configurable 50-2000 in F11 menu or TOML)
[*]Real-time counting: NPC count checked every 0.5 seconds during normal operation
[*]Emergency detection: NPC count checked EVERY FRAME to catch massive spawns (2000+ NPCs) before they crash
[*]PlaceAtMe hook: DISABLED (causes stack alignment crashes), uses reactive deletion instead
[/list]

[b]Normal Mode (under 2x threshold):[/b]
When NPC count exceeds threshold (e.g., 51-99 NPCs with default 50 threshold):
[list]
[*]Runs every 0.5 seconds (not every frame, minimal performance impact)
[*]Uses burden scoring system to prioritize which NPCs to remove:
  - Base burden: 10 points for all NPCs  - In combat: +20 points (expensive AI, high CPU usage)  - Complex AI packages: +15 points (pathfinding, decision-making overhead)  - Has magic effects: +10 points (spell processing, visual effects)  - 3D loaded: +10 points (rendering cost, GPU/CPU overhead)  - Duplicate instances: +30 points (2nd+ instance of same base NPC)  - Dead NPCs: -5 points (lower priority, handled by separate corpse cleanup)[*]Sorts NPCs by burden score (highest first)
[*]Removes excess NPCs with highest burden scores
[*]Configurable behavior: can disable NPCs temporarily (restore later) or delete permanently
[*]Restoration system: when NPC count drops below threshold, restores disabled NPCs behind player (out of view)
[/list]

[b]Emergency Mode (at 2x threshold or higher):[/b]
When NPC count reaches 2x threshold (e.g., 100+ NPCs with default 50 threshold):
[list]
[*]Activates immediately when detected (checked every frame for fast response)
[*]Skips burden calculation entirely (too slow for emergency)
[*]Deletes non-essential NPCs immediately (no disable/restore)
[*]Ultra-fast deletion: 500+ NPCs per frame when removing 500+ NPCs total
[*]Continues deleting every frame until count drops below 2x threshold
[*]Toast notification: "EMERGENCY: X NPCs! Deleting immediately." (if enabled)
[*]Designed to handle massive spawn events (console commands, mod bugs, script errors)
[*]Example: 2000 NPC spawn is caught and deleted within 4-5 frames (0.1 seconds at 60 FPS)
[/list]

[b]Per-Cell Baseline Learning (Optional):[/b]
[list]
[*]Learns normal NPC count for each cell you visit
[*]Adjusts threshold dynamically: baseline + delta (e.g., 30 baseline + 20 delta = 50 threshold)
[*]Allows higher NPC counts in naturally crowded areas (cities, battles)
[*]Allows lower NPC counts in normally empty areas (dungeons, wilderness)
[*]Configurable: can be disabled to use global threshold only
[/list]

[b]Dead Body Cleanup (Separate System):[/b]
[list]
[*]Default limit: 50 dead bodies (configurable)
[*]Runs when: dead body count exceeds limit OR near NPC limit with bodies present
[*]Same protection rules: never removes essential, unique, or quest NPCs (even if dead)
[*]Cleanup rate: configurable NPCs per cleanup cycle (default: 10)
[*]Respects same whitelist/blacklist keywords as live NPC management
[/list]

[b]Configuration Options:[/b]
[list]
[*]maxActors: NPC threshold (50-2000, default 50)
[*]disableInsteadOfDelete: temporarily disable NPCs instead of deleting (default: true)
[*]maxDisabledNPCs: max NPCs to keep disabled for restoration (default: 100)
[*]npcRestoreRate: how many NPCs to restore per cycle (default: 5)
[*]restoreBehindPlayer: only restore NPCs behind player (out of view) (default: true)
[*]maxDeadBodies: dead body limit (default: 50)
[*]npcCleanupRate: dead bodies to remove per cleanup (default: 10)
[*]usePerCellBaseline: enable per-cell baseline learning (default: false)
[*]cellNPCDelta: NPC count above baseline to trigger removal (default: 20)
[*]npcWhitelistKeywords: comma-separated keywords for NPCs to never remove
[*]npcBlacklistKeywords: comma-separated keywords for NPCs to remove first
[/list]

[*]Session-only: learned patterns are not persisted between game sessions
[*]Thread-safe: atomic operations for concurrent access
[*]Fast-path optimization: zero decoding overhead for cached sites
[/list]

[b]Log Files:[/b]
[list]
[*][font=Courier New]SkyrimCrashGuard.log[/font]: Main log with initialization, validation, and recovery attempts
[*][font=Courier New]CrashGuard-recovery-*.log[/font]: Detailed reports for each successful recovery (crash context, root cause, involved objects)
[*][font=Courier New]crash-*.log[/font] (CrashLogger/Trainwreck): Unrecoverable crashes that CrashGuard could not handle
[/list]

[center][size=5][b]Save Protection[/b][/size][/center]
[center][b][color=#ff7700]EXPERIMENTAL - NO GUARANTEES[/color][/b][/center]

[b]WARNING:[/b] When a crash is "recovered," the game continues running in a potentially corrupted state. Any saves made after a recovery may contain hidden corruption. 

[list]
[*][b]CoSave Coordination[/b]: Attempts to coordinate with cosave systems like S.L.A.C.K. when available (may not work with all cosave mods)
[*][b]State Validation[/b]: Attempts to detect obvious corruption (cannot detect all corruption types)
[*][b]Save/Load Monitoring[/b]: Attempts to reduce risk during save operations (cannot prevent all corruption scenarios)
[/list]

[b]Critical Limitations:[/b]
[list]
[*]These mechanisms [b]cannot guarantee save safety[/b]. They are best-effort only.
[*]Recovering from a crash means continuing with potentially corrupted memory, stack, or heap state
[*]Save corruption may not be immediately apparent and can manifest sessions later
[*]Deep corruption (stack/heap), interrupted writes, or third-party cosave tools can bypass all protections
[*][b]Always maintain external backups of your saves. Do not rely on this mod to protect your saves.[/b]
[/list]

[center][size=5][b]CrashLogger Compatibility[/b][/size][/center]

CrashGuard is designed to [b]cooperate[/b] with CrashLogger/Trainwreck, not compete with it. They work together to provide comprehensive crash coverage.

[b]How It Works:[/b]
[list]
[*]CrashGuard's VEH (Vectored Exception Handler) runs [b]before[/b] CrashLogger's exception handler
[*]When CrashGuard successfully recovers a crash: returns EXCEPTION_CONTINUE_EXECUTION, game keeps running, CrashLogger never sees it
[*]When CrashGuard cannot recover (or explicitly rejects the crash): returns EXCEPTION_CONTINUE_SEARCH, allowing CrashLogger to analyze and log the unrecoverable crash
[*]This cooperation is intentional: CrashGuard handles what it can, CrashLogger documents what it can't
[/list]

[b]Two Sets of Logs:[/b]
[list]
[*][font=Courier New]CrashGuard-recovery-*.log[/font]: Crashes CrashGuard successfully recovered (game continued running). These document "silent" recoveries that would have crashed the game without CrashGuard.
[*][font=Courier New]crash-*.log[/font] (CrashLogger): Crashes CrashGuard could not recover (game crashed). These are the unrecoverable crashes: stack overflow, heap corruption, system DLL crashes, or crashes after cascade limits exceeded.
[/list]

[b]Why Use Both:[/b]
[list]
[*]CrashGuard attempts to keep you playing through recoverable crashes (access violations, null pointers, vtable corruption)
[*]CrashLogger provides detailed analysis of unrecoverable crashes to help identify problematic mods
[*]Cross-reference both logs for a complete picture of your session's stability
[*]If you see many CrashGuard recoveries but no CrashLogger crashes: CrashGuard is working well
[*]If you see both: CrashGuard is handling some crashes but others are too severe to recover
[/list]

[center][size=5][b]Configuration[/b][/size][/center]

All settings are in [font=Courier New]Data/SKSE/Plugins/SkyrimCrashGuard.toml[/font]. Key sections:

[b][General][/b]: Enable/disable the mod, set log level
[b][VEH][/b]: Vectored exception handler settings
[b][ResourceLimiter][/b]: Actor/reference limits, auto-culling thresholds
[b][PapyrusValidation][/b]: Native function parameter validation
[b][UserNotifications][/b]: Control which crash severities prompt for user input
[b][Hotkeys][/b]: Menu toggle key (default: F11)
[b][ImGui][/b]: Set [font=Courier New]disableMenu = true[/font] to fully suppress F11 menu
